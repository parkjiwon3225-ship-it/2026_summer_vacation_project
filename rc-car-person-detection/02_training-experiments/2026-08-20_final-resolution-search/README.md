# 2026-08-20 최종 입력 해상도·seed 탐색

## 목적

고해상도 screening에서 얻은 성능 향상이 seed에 재현되는지 확인하고, Raspberry Pi 배포에 사용할 정확도·입력 비용·Recall 균형점을 고르는 실험이다. 모든 run은 같은 custom anchor-free 구조(FPN 48, expansion 2.0, box weight 2.0, quality weight 1.0, center radius 1.5)를 사용하고 입력 크기와 seed를 중심으로 비교했다.

## 탐색 흐름

```text
320×240 baseline
  → 512/576/640/704/768 screening (R32~R37)
  → seed 확장과 100 epoch 관찰 (R38~R44)
  → 실제 배포 후보 해상도 448/512/576 비교 (R45~R50)
  → R46 448×336 seed15, epoch 25 선택
```

전체 수치는 [`experiment_summary.csv`](experiment_summary.csv)에 있다. 같은 run이 여러 회수 ZIP에 중복된 경우 run 이름을 기준으로 deduplicate하고 가장 완전한 history를 남겼다.

## 왜 mAP 최고인 R33/R36/R49가 아니라 R46인가

최종 모델 선정 목표는 validation mAP 단독 최대화가 아니라 실제 RC-Car에서의 사람 누락, 입력 비용, INT8 경량화 안정성을 함께 만족하는 것이다.

- R49는 mAP와 Precision이 높지만 Recall 0.2351, small recall 0.0176으로 누락 위험이 컸다.
- R33/R36은 screening 성능이 높았지만 576·704 입력 비용이 증가하고 seed에 따른 변동도 확인됐다.
- R46은 448×336에서 Recall 0.4129와 small recall 0.1550을 확보해 최종 후보군 중 균형이 가장 좋았다.
- 448×336은 기존 320×240과 같은 4:3 비율이라 원본 카메라 좌표 복원도 단순하다.

따라서 R46의 epoch 25 `best.pt`를 FP32 기준 checkpoint로 고정하고, 이후 selective INT8 실험은 모두 이 가중치에서 파생했다.

## 보관 파일

```text
runs/<run>/

  history.csv

runs/r46_final448_seed15_100e/

```

`last.pt`, 중복 회수 ZIP, 데이터셋은 저장소 용량과 재배포 문제 때문에 포함하지 않는다.
