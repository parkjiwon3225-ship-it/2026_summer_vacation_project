## 1. 결론

1. **현재 1순위 방향은 `FPN 48 / expansion 2.0 / LR 0.001` 경량 모델이다.**
   - 최고 mAP50:95: **0.2525**
   - 고정 threshold 0.25 기준 최고 checkpoint의 Precision / Recall / F1: **0.5857 / 0.5576 / 0.5713**
   - 작은 사람(16~32 px) Recall: **0.5294**
   - 파라미터: **323,546개**, 기준 모델보다 6.2% 적음
   - 학습 처리량: 기준 모델보다 약 10.4% 빠름
   - peak VRAM: 기준 모델보다 약 15.5% 적음

2. **계속 검토할 보조 방향은 기준 모델과 낮은 학습률이다.**
   - 기준 모델은 최고 mAP 0.2393으로 2위이고 Precision이 높다.
   - LR 0.0005는 수렴이 느리지만 최고점이 59 epoch로 가장 늦고, Precision이 높다.
   - 따라서 2차에서는 경량 모델에 LR 0.0005~0.001을 결합해 보는 것이 타당하다.

3. **이번 조건에서는 아래 설정을 중단한다.**
   - FPN 80 + expansion 2.5: 더 크고 느리지만 mAP와 작은 사람 Recall 모두 낮음
   - center radius 2.0: 기준보다 mAP·Recall·작은 사람 Recall 하락
   - box loss weight 3.0: Precision은 높지만 Recall과 F1이 크게 하락

4. **100 epoch 전체를 기다릴 필요가 없었다.**
   - 여섯 실험의 최고 mAP 발생 epoch는 18, 18, 37, 37, 37, 59였다.
   - validation loss 최저점은 21~38 epoch였다.
   - 이후에는 train loss는 계속 감소하지만 validation loss가 상승하고 mAP가 정체·하락하는 과적합 패턴이 나타났다.
   - 2차 실험은 과적합 이후의 불필요한 시간을 줄이면서 후보 간 차이를 확인할 수 있도록 **70 epoch**로 설정했다.

## 5. 실험별 해석

### results.4 — FPN 48 경량

- 모든 핵심 지표에서 종합 1위다.
- 기준 모델보다 파라미터가 6.2% 적고, 학습 처리량은 10.4% 높고, peak VRAM은 15.5% 낮다.
- 특히 small Recall이 0.5294로 기준 0.3377보다 크게 높다.
- Precision은 기준보다 낮지만 Recall이 크게 올라 F1과 mAP가 개선됐다.
- 마지막 48 epoch mAP도 0.2472로 최고점 0.2525와 가까워 비교적 안정적이다.
- **2차 실험의 중심축으로 유지한다.**

### results.2 — 기준 모델

- 최고 mAP 0.2393으로 2위이며 Precision 0.7502가 강점이다.
- 최고점과 validation loss 최저점이 모두 37 epoch에 나타났다.
- 80 epoch에서는 mAP가 0.2096까지 하락해 이후 학습 이득이 없다.
- 이 노트북만 PyTorch 2.5.1+cu121이고 나머지는 2.3.1이므로, 엄밀한 단일 변수 비교에는 소프트웨어 버전이라는 교란 요인이 있다.
- **2차에서는 모든 노트북의 PyTorch 버전을 통일해야 한다.**

### results.1 — LR 0.0005

- 최고 mAP 0.2299로 3위지만 59 epoch까지 천천히 개선됐다.
- 낮은 LR은 수렴 속도를 늦추고 Precision을 유지하는 성향을 보였다.
- 기준보다 확실히 우월하다고 보기는 어렵지만, FPN 48과 결합할 가치가 있다.
- **단독 방향은 중단하고, 경량 모델의 LR 후보로 유지한다.**

### results.3 — center radius 2.0

- 할당되는 positive 수는 늘지만, mAP·Recall·tiny/small Recall이 모두 기준보다 하락했다.
- 넓은 center sampling이 작은 사람에서 모호한 positive를 늘린 것으로 추정된다.
- **radius 2.0은 중단하고 1.5를 유지한다.**

### results.5 — FPN 80 + expansion 2.5

- 파라미터 440,994개, peak VRAM 0.532 GiB로 가장 크다.
- 최고 mAP는 18 epoch의 0.2129이고 이후 하락했다.
- 작은 사람 Recall이 낮고 과적합이 가장 이르게 시작됐다.
- **현재 데이터와 320×240 입력에서는 용량 확대가 이득이 아니므로 중단한다.**

### results.6 — box weight 3.0

- Precision은 0.8058로 가장 높지만 Recall 0.2576, F1 0.3904로 크게 낮다.
- 위치 회귀를 과하게 강조하면서 검출 수와 작은 사람 Recall을 희생한 형태다.
- **box weight 3.0은 중단하고 2.0을 유지한다.**

## 6. 왜 여섯 Anaconda Prompt가 멈췄는가

### 결과 파일로 확정할 수 있는 사실

- 학습 코드는 100 epoch를 끝내기 전 자동 종료하는 early stopping이나 시간 제한이 없다.
- 모두 100 epoch 미만에서 중단됐다.
- 마지막 history 행은 완전하고, 같은 epoch의 `last.pt`가 정상 저장됐다.
- loss 값에는 NaN/Inf가 없었고, 경고가 발생한 후에도 수십 epoch를 계속 학습했다.
- Python traceback이나 CUDA OOM 기록은 압축 결과에 없다.
- 다섯 대는 약 13.1~13.8시간 연속 실행 후 23:46~00:15에 종료됐다.
- 경량 모델 한 대만 약 6.9시간 실행 후 17:21에 별도로 종료됐다.

### 판단

**학습 설정이나 공통 데이터 오류가 여섯 작업을 종료시킨 것은 아니다.** 동일 데이터 오류라면 같은 seed와 데이터 순서에서 비슷한 epoch에 멈춰야 하지만, 실제 마지막 epoch는 48~93으로 다르다. 또한 경고 발생 epoch와 종료 epoch도 일치하지 않는다.

가장 가능성이 높은 원인은 Windows 또는 학교 장비의 외부 실행 중단이다.

- 23:46~00:15에 몰린 다섯 대: 학교의 예약 종료·재부팅·전원 정책·절전 정책 가능성이 높음
- 17:21의 경량 모델 한 대: 해당 노트북만 절전, 전원 분리, 사용자 로그오프, 창 종료 또는 개별 드라이버/OS 이벤트가 있었을 가능성

단, 결과 폴더에는 Windows 이벤트 로그가 없으므로 정확한 원인 코드는 확정할 수 없다. 다음 방문 때 각 노트북의 Windows System 이벤트에서 2026-08-12 종료 시각 주변의 이벤트 ID 41, 42, 1074, 6005, 6006, 6008을 확인해야 한다.

## 7. 반복된 NaN/Inf 경고의 실제 의미

- 모든 train/valid classification·quality·box·total loss는 유한한 값이다.
- NaN/Inf가 발생한 열은 `train_gradient_norm`뿐이다.
- 경고는 AMP scale이 32768~65536까지 성장한 뒤 약 16~20 epoch부터 반복되었다.
- 따라서 모델 loss 전체가 붕괴한 것이 아니라, mixed precision 역전파에서 일부 step의 gradient가 overflow한 현상으로 판단한다.
- GradScaler가 scale을 낮추고 업데이트를 건너뛰므로 즉시 종료되는 오류는 아니지만, 반복되면 학습 효율이 떨어질 수 있다.

2차 실험 전 권장 조치:

1. 모든 실험의 `amp_growth_interval`을 4000에서 **20000**으로 늘려 scale 성장을 늦춘다.
2. loss 비정상과 gradient 비정상 경고를 분리한다.
3. non-finite gradient step 수를 별도 기록한다.
4. 모든 노트북의 PyTorch를 동일 버전으로 맞춘다.

## 8. 2차 병렬 실험 설계 및 시작 상태

공통값:

- 70 epoch
- image 320×240, batch 8
- box weight 2.0, center radius 1.5
- AMP on, `amp_initial_scale=1024`, `amp_growth_interval=20000`
- 동일 PyTorch/CUDA 버전

| 노트북 | 설정 | 확인 목적 |
|---:|---|---|
| 1 | FPN48, exp2.0, LR 0.001, 새 seed | 1차 우승 설정 재현성 확인 |
| 2 | FPN48, exp2.0, LR 0.00075 | 우승 설정 주변 LR 탐색 |
| 3 | FPN48, exp2.0, LR 0.0005 | 경량 + 낮은 LR 결합 |
| 4 | FPN40, exp2.0, LR 0.001 | 더 작은 모델의 정확도/속도 경계 |
| 5 | FPN56, exp2.0, LR 0.001 | 48과 64 사이 최적 폭 확인 |
| 6 | FPN48, exp2.5, LR 0.001 | 좁은 FPN을 유지한 채 backbone 용량만 증가 |

2026-08-13 오전, 위 여섯 설정의 학습을 학교 노트북 6대에서 시작했다. 두 대에서는 Windows 애플리케이션 제어 정책이 Conda 환경의 `_ctypes`, `_overlapped`, Pillow 또는 PyTorch DLL을 차단하는 `WinError 4551`이 발생했다. 해당 장비들은 Python 3.11 기반 Conda 환경과 PyTorch 2.5.1+cu121을 새로 설치한 뒤 검증을 통과해 학습을 시작했다.

2차 결과에서는 같은 70 epoch 범위에서 best mAP50:95, F1, tiny/small Recall, 모델 크기, 추론 속도를 비교해 최종 1~2개 방향으로 좁힌다. 환경 버전 차이는 결과 해석 시 교란 요인으로 별도 기록한다.

집의 대여 노트북에서는 `FPN48 / expansion 2.0 / LR 0.00075 / 새 seed / 100 epoch`를 실행해 학교 실험을 보조하고 장시간 안정성을 관찰한다.
